1. La commande git status permet d’afficher les fichiers suivis ou non, ceux qui sont prêts à être commités ou non. Dans mon cas, elle indique que README.md est un fichier non suivi (untracked).
2. Après git add, git status montre que les fichiers sont maintenant dans l’index (staging area) et prêts à être commités. Ils ne sont plus marqués comme untracked.
3. La commande git add . envoie les fichiers modifiés ou créés dans l’espace de staging (index), ce qui les prépare à être commités. Ils ne sont pas encore enregistrés dans l’historique Git.
5. La commande git log permet d’afficher l’historique des commits, avec leur hash, auteur, date et message associé.
6. git diff montre les différences entre les fichiers modifiés et ceux dans l’index (staging area). git diff --staged montre les différences entre l’index et le dernier commit. Donc, le premier montre ce qui n’a pas encore été ajouté, le second ce qui est prêt à être commité.
7. git show affiche les détails d’un commit (auteur, date, modifications). git status montre les fichiers modifiés ou en attente de commit. git diff montre les différences non encore ajoutées. git log montre l’historique des commits.
